# Step A 粗筛方案设计探讨

> 文档目的：整理 Step A（批内粗筛）现有方案、已知问题、讨论结论及候选替代方案，供多方 AI 参考并提出改进建议。
> 最后更新：2026-04-01

---

## 一、系统背景

### 整体架构

本系统是一个多批次情报处理 pipeline，处理游戏行业外部情报，目标是从海量信号中识别**可操作的战略机会**。

```
Phase 2.1（解码）→ Phase 2.2（机会判断）→ Phase 2.3（行动设计）→ Phase 2.5（复盘）
```

核心挑战在 Phase 2.2（机会判断），信号以批次方式流入，单批次可能 5–100 条，
而**构成一个机会的信号可能来自不同批次**（跨批次问题）。

### Phase 2.2 内部流程（当前版本）

```
来自 2.1 的 enriched_signals
        │
        ▼
    Step A：批内粗筛
    （单次 LLM 调用，haiku 级别）
    输出：
    - signal_groups：本批次内可直接组合的信号组 → 送 Step C
    - isolated_signals：孤立信号（含角色标注） → 送 Step B
        │
        ├─ signal_groups → Step C（机会判断，复用 judge()）
        │
        └─ isolated_signals → Step B：与 Signal Store 历史信号做匹配检索
                                        │
                                        ├─ 找到历史伙伴 → Step C（跨批次组合判断）
                                        │
                                        └─ 无伙伴 → 写入 Signal Store（pending 状态等待）
```

### Signal Store

持久化存储，保存所有 pending / matched / contributed 状态的信号。
Step B 用它做跨批次匹配，确保"这批来了一个信号，下批来了配套信号"时能组合成机会。

## 二、Step A 当前实现

### 文件位置

`data-layer/projects/proj_004/phase2.2_implementation/step_a_cluster.py`

### 工作原理

Step A 的职责是：对本批次信号做一次 LLM 调用，输出两件事：
1. 哪些信号可以在本批次内直接组合（`signal_groups`）
2. 每条信号的角色标注（`roles` / `needs` / `domains` / `waiting_for_text`）

**LLM 路径**：单次调用（deepseek/haiku 级），prompt 让 LLM 根据"逻辑互补"原则识别可组合的信号组。

**规则 Fallback**：LLM 失败时，按 `signal_type` 静态表推断角色，所有信号视为孤立。

### 当前 Prompt 的分组逻辑

```
分组依据是"逻辑互补"，不是"语义相似"
典型组合：外部压力信号（催化剂）+ 需求侧变化信号 + 资源到位信号
```

注意：**Prompt 设计是正确的**（逻辑互补），问题在于 LLM 实际执行时，因为信号的
描述信息有限（只有 label + description[:100] + signal_type + intensity），
LLM 倾向于退化到按语义相似性或领域重叠做粗糙分组，而不是做真正的逻辑互补判断。

## 三、已识别的核心问题

### 问题 1：Step A 的分组污染了 Step C 的判断前提

**旧版行为（无 Step A）**：
Step C（judge()）直接接收全量信号，LLM 做端到端推理：
- 自主决定哪些信号有关联
- 自主识别逻辑链条
- 自主产出机会列表

**新版行为（有 Step A）**：
Step A 先做分组，Step C 接收已分组的信号子集，被迫在这个子集里找机会。

**问题本质**：
Step A 将"相关性判断"从 Step C 手里提前剥离出来，但 Step A（haiku 级、上下文信息少）
没有 Step C 的完整推理能力。Step A 的错误分组会成为"前置假设"污染 Step C——
Step C 虽然看到更少的信号（理论上更好判断），但它在错误的前提下判断，反而精度下降。

类比：给侦探 5 条"已被确认属于同一案件"的线索（实际来自两个不同案件），
比给他 100 条让他自己筛，更容易被误导。

### 问题 2：领域/标签重叠的分组方案系统性漏掉跨域机会

即使修复 LLM 实际执行的退化问题，**领域/标签分组本身就有结构性缺陷**：

**游戏行业机会的典型逻辑链条是跨域的**：

| 机会类型 | 信号1 | 信号2 | 信号3 |
|----------|-------|-------|-------|
| "监管倒逼整合" | 监管域：DMA新规 | 资本域：某大厂战略并购资金就位 | 市场域：中小团队估值跌至低点 |
| "AI降低独立游戏门槛" | 技术域：生成式AI代码工具成本骤降 | 市场域：独立游戏平台月活创新高 | 团队域：大厂核心研发出走创业 |
| "移动端竞争格局重塑" | 团队域：头部团队核心人员流失 | 技术域：新引擎降低移植成本 | 监管域：应用商店费率调整 |

这些机会的信号来自完全不同的领域，但**逻辑链条上是强互补的**。
按领域重叠分组，这些跨域组合会被拆散——每条信号单独进入 Step B，
依赖 Signal Store 历史匹配，而历史匹配的精度远低于直接在同一个 Step C 上下文里推断。

**估算比例**：在游戏行业情报场景中，构成可操作机会的信号逻辑链：
- 纯单域（信号来自同一领域）：约 30–40%
- 跨域（信号来自 2 个以上不同领域）：约 60–70%

即当前 Step A 按领域/标签分组，会**系统性漏掉约 60% 的可操作机会**。

### 问题 3：小批次和大批次的场景需求不同

| 场景 | 信号数量 | Step A 的实际价值 |
|------|----------|-------------------|
| 小批次（< 20 条） | 少 | 几乎没有价值；全量送 Step C 更好，token 消耗可控 |
| 中等批次（20–50 条） | 中 | 需要粗筛，否则 Step C 的 context 太长影响质量 |
| 大批次（50+ 条） | 多 | 粗筛是必要的，否则 token 消耗和推理质量均有问题 |

## 四、已决策的处理方式

**小批次（当前采用）**：取消 Step A，全量送 Step C。
- 已确认可行，精度更高，token 消耗可控
- 具体阈值待定（初步建议 ≤ 20 条）

**大批次**：方案仍在探索阶段，这是本文档的核心问题。

---

## 五、待探讨的核心问题

**如何设计一个大批次下的信号粗筛方案，使其：**

1. **保留跨域机会的组合可能**：不因为领域/标签不同就拆散逻辑上互补的信号
2. **减少 Step C 的输入规模**：避免 50+ 条信号全量送 Step C（context 过长、噪音过多）
3. **不污染 Step C 的判断前提**：Step A 的分组结论不能成为 Step C 的硬性前提，应该是"建议"而非"约束"
4. **成本可控**：Step A 应该是轻量的（haiku 级 LLM 或规则），不能比 Step C 本身更贵

## 六、候选方案草稿（供讨论）

### 方案 A：信号角色互补匹配（强化当前方案）

**思路**：
放弃领域/标签，改为纯角色互补匹配。每条信号标注 `role`（催化剂/需求证据/资源验证/执行风险），
根据 `ROLE_COMPLEMENTS` 表识别互补信号对，优先将有互补角色的信号组合。

**优点**：
- 天然支持跨域（监管信号=催化剂，可以和任何域的需求证据配对）
- 逻辑互补判断比语义相似更接近机会发现的本质

**缺点**：
- 角色标注本身依赖 LLM（haiku 级），标注准确性有限
- 规则表（`ROLE_COMPLEMENTS`）是静态的，无法覆盖复杂的多信号互补模式

**当前代码已实现此思路的框架**，但 LLM 执行时退化到语义相似。
解决方向：强化 prompt，在 signals_summary 中增加更多信号的"逻辑维度"（不只是 label + type），
让 LLM 有足够的信息做逻辑互补判断而不是语义相似判断。

---

### 方案 B：两阶段漏斗（粗筛 + 精判）

**思路**：
Step A 不做分组，只做"信号质量过滤"和"噪音剔除"。
通过规则（intensity < 阈值、confidence < 阈值、信号过老等）剔除低质量信号，
剩余高质量信号全量送 Step C。

**优点**：
- 不产生分组假设，不污染 Step C
- 规则层可靠，无 LLM 不确定性
- 实现简单

**缺点**：
- 只能减少信号数量，不能解决大批次（50+ 条高质量信号）的 context 长度问题
- 如果信号质量普遍不错，过滤效果有限

---

### 方案 C：滑动窗口（多次小批量送 Step C）

**思路**：
不分组，而是把大批次信号按窗口切分（例如每 10 条一组），
多次调用 Step C，每次结果做去重合并。

**优点**：
- 不产生分组假设
- 每次 Step C 的 context 可控
- 实现简单

**缺点**：
- **窗口切分会导致跨窗口的逻辑链被拆散**——本质上只是换了一个维度的"分组错误"
- 多次调用 Step C 成本高（Step C 使用 sonnet 级，比 Step A 贵 10–20 倍）
- 需要去重合并逻辑（不同窗口发现同一机会时如何合并）

---

### 方案 D：LLM 做"机会假说生成"，再做信号匹配

**思路**（尚未实现）：

反转流程：不让 Step A 决定"哪些信号可以组合"，而是：
1. Step A（轻量）：让 LLM 看全量信号摘要，生成 3–5 个"机会假说"
   （例如："监管收紧 + 资本充足 + 团队流动 = 整合机会"）
2. 信号匹配：对每个假说，从信号池里匹配支持/反对证据
3. Step C：对每个有足够支持证据的假说，做完整判断

**优点**：
- Step C 带着明确的假说方向进来，判断质量更高
- 假说生成阶段天然支持跨域（因为是从"机会方向"出发，而不是从"信号分组"出发）
- Step C 每次只验证一个假说，context 可控

**缺点**：
- Step A 的假说生成质量决定了召回上限（LLM 没有想到的假说方向会被遗漏）
- 实现复杂度高：信号-假说匹配需要新模块
- 需要评估假说生成阶段的 token 成本

---

### 方案 E：保留 Step A 但降级为"建议"（软约束）

**思路**：
保留 Step A 的分组输出，但改变 Step C 的使用方式：
- Step A 的分组结果作为"建议相关信号"标注，而非"隔离的子集"
- Step C 仍然接收全量（或更大范围的）信号，Step A 的分组通过 prompt 的方式告知：
  "根据初步分析，信号 A、B、C 可能相关，请在判断时重点关注它们的逻辑关联性，但不限于此"
- Step C 可以自由突破 Step A 的建议分组，发现跨组的机会

**优点**：
- 不污染判断前提（是建议，不是约束）
- 保留 Step A 对 Step C 的"注意力引导"价值
- 改动量小

**缺点**：
- 实际效果取决于 Step C prompt 工程，不确定性高
- 大批次时 Step C 仍然需要处理全量信号，context 过长问题未解决

## 七、讨论问题列表（供 AI 参考回答）

以下是需要讨论的核心设计问题，欢迎提出方案建议：

### Q1：如何在不产生错误分组假设的前提下，有效降低大批次下 Step C 的 context 长度？

背景：
- 每条信号约 150–300 tokens（含 label、description、source、打分）
- 50 条信号全量 = 约 7500–15000 tokens 的信号部分（加上 prompt 框架约 20000 tokens）
- sonnet 级模型处理 20000 tokens 仍然可以，但质量有下降趋势

问题：如何在不切断跨域逻辑链的前提下，把送入 Step C 的信号数量控制在 10–20 条？

### Q2：方案 D（机会假说生成）的可行性和潜在问题？

特别关注：
- 在信号质量参差不齐、假信号比例高的情况下，假说生成是否仍然可靠？
- 假说的"遗漏"问题如何处理？（LLM 没有想到的假说方向）
- 与当前 Signal Store 跨批次架构如何整合？

### Q3：有没有不依赖 LLM 的粗筛方案，能在大批次下有效识别"可能互补"的信号对？

背景：
- 当前依赖 LLM 做 Step A，但 LLM 会退化到语义相似而不是逻辑互补
- 是否有基于向量嵌入、图结构、规则引擎的方案可以替代？
- 需要考虑：信号的"逻辑互补"是语义层面还是结构层面？

### Q4：方案 A（角色互补匹配）的增强方向？

当前 Step A prompt 已经设计为"逻辑互补"分组，但实际 LLM 执行退化到语义相似。

- 如何通过 prompt 工程解决这个问题？
- 信号的 `description[:100]` 是否提供了足够的语义信息让 LLM 做逻辑互补判断？
- 是否需要在 2.1 解码阶段为每条信号增加更多的"逻辑维度"标注（例如：它代表什么变化？变化的方向？影响的对象？）？

### Q5：大批次的阈值和处理策略分级？

是否可以设计一套分级策略：
- ≤ 20 条：全量送 Step C，不过 Step A
- 21–50 条：Step A 做角色互补匹配，分组不超过 3 组，Step C 每组独立判断
- 50+ 条：Step A 生成机会假说，每个假说独立送 Step C 验证

这种分级策略的优劣势？

## 八、当前代码关键片段

### Step A 的角色互补表（规则层）

```python
ROLE_COMPLEMENTS = {
    "catalyst":            ["demand_evidence", "resource_validation", "competitive_gap"],
    "demand_evidence":     ["catalyst", "resource_validation"],
    "resource_validation": ["catalyst", "demand_evidence"],
    "competitive_gap":     ["catalyst", "resource_validation"],
    "execution_risk":      ["catalyst", "demand_evidence"],
    "timing_signal":       ["catalyst", "demand_evidence", "resource_validation"],
    "negative_validator":  [],
}
```

### Step A LLM 分组依据（当前 prompt 核心）

```
识别哪些信号可以组合成一个完整的机会论点。注意：
- 组合依据是"逻辑互补"，不是"语义相似"
- 典型组合：外部压力信号（催化剂）+ 需求侧变化信号 + 资源到位信号
```

### Step C 调用方式（当前）

```python
# signal_groups 里每个 group 单独送 judge()，硬隔离
for group in step_a_result.signal_groups:
    group_request = self._build_group_request(request, group)
    result = self.judge(group_request)
```

### Step B 匹配策略（孤立信号与历史信号）

孤立信号通过 Signal Store 的分层漏斗匹配历史伙伴：
1. 精确匹配（signal_type + domains 完全重叠）
2. 宽松匹配（roles needs 互补）
3. 时效性过滤（过老的信号降权）
