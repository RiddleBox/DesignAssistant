# Step B 机会形成边界规则稿

## 1. 目标

`Step B` 的职责，不是判断某个候选在自己的类别里是否“足够强”，而是判断：

- 当前孤立信号与历史库存组合后，是否已经形成**可交给 Step C / 2.3 消费的最小机会逻辑**。

因此，`Step B` 的核心边界应收敛为：

- **形成机会** → 进入 `Step C`
- **尚未形成机会，但具有结构成长价值** → 保留在 `Signal Store`
- **既未形成机会，也无明显成长价值** → 丢弃

---

## 2. 三类候选的语义

### 2.1 `signal_entry`

表示历史库存中的**单条待配对信号**。

它的含义是：

- 可以和当前信号形成关系
- 可能补到某个缺口
- 但默认仍只是“机会前状态”

规则：

- **形成关系 ≠ 形成机会**
- 单条历史信号即使强，也不应只因为“桶内很突出”就上升

### 2.2 `emerging_link`

表示历史信号之间已经存在某种**关系痕迹**。

它的含义是：

- 这些信号之间已有结构性关联
- 但关联本身不等于机会成立

规则：

- **形成 link ≠ 形成机会**
- 如果当前信号只是在 link 上增加了关系强度，但仍未形成机会语义，则只能继续保留

### 2.3 `scenario_memory`

表示已经有一定结构的**半成品场景**。

它的含义是：

- 已经跨过单点和单纯关系层
- 但仍可能只是“部分 scenario”
- 只有被当前信号补成最小机会闭环，才应上升

规则：

- **形成 partial scenario ≠ 形成机会**
- `scenario_memory` 不是自动上升通道，只是更成熟的候选容器

---

## 3. 统一上升口径

不论候选来自：

- `signal_entry`
- `emerging_link`
- `scenario_memory`

都必须通过同一个问题：

> 当前组合是否已经形成**最小可解释机会逻辑**？

只有答案为“是”，才允许上升到 `Step C`。

### 3.1 最小可解释机会逻辑的最低含义

至少应满足以下语义，而不是只满足其中一个局部指标：

- 不只是有关系，而是已经出现**机会语义**
- 不只是补了一个槽，而是已经具备**最小闭环**
- 不只是结构分数高，而是已经能作为后续判断输入被消费

### 3.2 不足以上升的典型情况

以下情况原则上都不应直接上升：

- 仅形成 `signal pair`
- 仅命中 `emerging_link`
- 仅补成部分 `scenario`
- 仅在本类别里分数高
- 仅具备较高 `promotion_score / option_value_score`

这些都可以成为“继续保留”的理由，但不是“立即上升”的充分条件。

---

## 4. 推荐的 Step B 输出语义

### 4.1 推荐路由

- `step_c_ready`
  - 已形成最小机会逻辑
  - 可以进入 `Step C`

- `store_for_later`
  - 仍属机会前状态
  - 有结构成长价值
  - 保留到 `Signal Store`

- `discard`
  - 既未形成机会，也无明显保留价值

### 4.2 不推荐继续使用的强语义命名

以下命名容易把 `Step B` 误解成“机会等级预判层”：

- `primary`
- `exploration`

原因：

- 它们更像在表达“哪个机会更重要”
- 而不是表达“是否已形成机会”

如需兼容旧链路，可短期保留别名，但正式口径应切到：

- `step_c_ready`
- `store_for_later`

---

## 5. 载体优先级与机会优先级要分开

`Step B` 可以做的是：

- 在多个可上升候选中，选择**更适合承载本次上升**的主载体

例如默认优先：

- `scenario_memory`
- `emerging_link`
- `signal_entry`

但这只是：

- **载体优先级**

不是：

- **机会优先级**
- **行动姿态优先级**

后者不应由 `Step B` 过早承载。

---

## 6. 与 Step C / 2.3 的职责边界

### 6.1 `Step B` 负责

- 历史候选召回
- 不同成熟度候选的匹配
- 判断是否已形成最小机会逻辑
- 选择哪一个候选作为上升载体

### 6.2 `Step B` 不负责

- 正式机会等级判断
- 行动姿态判断
- 资源承诺判断
- 推进 / 回退设计

这些应保留给 `Step C / 2.3`。

---

## 7. 边界测试建议

至少覆盖以下边界：

1. **单强 signal 不自动上升**
   - 强 `signal_entry` + 当前信号
   - 仅形成最小关系，不形成完整机会
   - 结果应为 `store_for_later`

2. **emerging_link 不自动上升**
   - 命中 link 但未形成机会闭环
   - 结果应为 `store_for_later`

3. **scenario_memory 仅在闭环成立时上升**
   - 命中 scenario 且当前信号补齐关键缺口
   - 形成最小机会逻辑
   - 结果应为 `step_c_ready`

4. **scenario 优先于 signal 作为载体**
   - 两者都被召回时
   - 若 scenario 已成形、signal 仍只是前状态
   - 应优先上升 scenario

---

## 8. 一句话结论

> `signal_entry`、`emerging_link`、`scenario_memory` 是不同成熟度的机会前状态；它们是否上升，不取决于“在本类别里有多突出”，而取决于是否已经形成可被 `Step C / 2.3` 消费的最小机会逻辑。
