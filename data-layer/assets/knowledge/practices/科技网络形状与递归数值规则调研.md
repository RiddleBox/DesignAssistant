## 主题 A · 文明7 科技/市政线形状 【高优先】

### A1. 三时代科技与市政数量

> 🤖 基于 Civ7 发布信息（2025.2）和社区整理。Civ7 Wiki 页面被 Cloudflare 拦截，以下为训练知识估算。

| 时代 | 科技数 | 市政数 | 合计 |
|------|--------|--------|------|
| Antiquity（远古） | ~15-20 | ~15-20 | ~30-40 |
| Exploration（探索） | ~15-20 | ~15-20 | ~30-40 |
| Modern（现代） | ~15-20 | ~15-20 | ~30-40 |
| **全游戏合计** | **~45-60** | **~45-60** | **~90-120** |

> 👥 对比 Civ6: 基础游戏约 68 个科技 + 50 个市政 = ~118 节点。Civ7 的节点数相近，但被切割进 3 个时代。

### A2. 前置数与 AND/OR 关系

| 维度 | 数据 | 来源 |
|------|------|------|
| 平均前置数 | **1-3 个** | 🤖 训练知识 |
| 最多前置 | **4-5 个**（时代末期科技） | 🤖 |
| AND/OR | 绝大多数为 **AND**（所有前置必须满足） | 🤖 |
| OR 前置 | 极少，Civ6 中存在少量（如某些单位的一个前置即可），Civ7 延续此设计 | 🤖 |

> 📌 Civ 系列设计原则（Sid Meier 访谈）：科技树故意设计为"宽而浅"，平均深度 ~5-7 层，确保玩家始终有多个可选方向。

### A3. 扇出度（一个科技解锁几个后续）

| 维度 | 数据 | 来源 |
|------|------|------|
| 平均扇出 | **1.5-2.5 个** 后续科技 | 🤖 |
| 最大扇出 | **4-6 个**（核心枢纽科技，如 Writing/Printing） | 🤖 |
| 解锁非科技内容 | 每个科技通常还解锁 1-3 个单位/建筑/奇观 | 🤖 |
| 伪选择问题 | 扇出=1 的科技形成"必经之路"（瓶颈科技），Civ 故意保留少量瓶颈以控制节奏 | 👥 设计讨论 |

### A4. 时代门控机制

> 🤖 + 👥

| 维度 | 数据 |
|------|------|
| Civ6 时代推进 | 研究完当前时代所有科技 → 下一时代解锁（非强制，可跳时代） |
| Civ7 时代推进 | **强制时代过渡**：研究满一定数量的里程碑科技后，触发 Crisis 事件 → 新时代开始；部分科技/市政/单位在过渡时**废弃**（Civ7 核心创新） |
| 时代内科技门控 | 纯前置依赖（AND），无额外条件 |
| 尤里卡/灵感（Civ6） | 触发特定条件 → 该科技研究量减 **40%（尤里卡）或 40%（灵感）**；Civ7 改为 Narrative Events 系统，非固定百分比 |

### A5. 主线 vs 平行线

> 🤖

| 维度 | Civ6/7 模式 |
|------|-------------|
| 科技树拓扑 | **多条平行线**，无单一线性的"主线" |
| 平行线数 | 通常 **4-6 条平行线**：军事 / 经济 / 科技 / 文化 / 航海 / 政治 |
| 跨线依赖 | 偶尔交叉——如 Writing 属于科技线但解锁文化线的一些内容 |
| 玩家并行选择 | 任何时候可选的"下一步科技"通常 **3-8 个** |

### A7. Civ7 vs Civ6 核心变化

> 🤖 + 👥

| 变化 | 说明 |
|------|------|
| **时代强制重置** | Civ7 最大变化：每个时代开始，大量过时的科技/单位失效，防止雪球 |
| **科技树缩小** | 单个时代的科技树比 Civ6 小，但 3 个时代叠加速率重置 |
| **叙事事件替代尤里卡** | 不再有固定的 40% 折扣，改为情境触发的事件链 |
| **市政树独立但并行** | 市政和科技在并行轨道上，各自有独立的前置依赖网 |
| **领袖与文明分离** | 领袖不再绑死文明，影响科技/市政选择——但这是战略层变化，非形状变化 |

### B10. 每级科技的底层资源放大倍数

> 🟢 基于 Factorio Wiki 科学包配方数据直接推算

| 科技梯度 | 铜需求量增幅 | 铁需求量增幅 | 原油需求量 | 增幅模式 |
|----------|-------------|-------------|-----------|---------|
| 红 → 绿 | ×1.5 | ×2.75 | 0 | 线性跳 |
| 绿 → 灰 | ×0.33 | ≈ | 0 | 军事线分离 |
| 绿 → 蓝 | ×5 | ×2.2 | 引入原油 | **质变跃迁** |
| 蓝 → 紫 | ×2.6 | ×4.4 | ×1.8 | 大幅跳跃 |
| 紫 → 黄 | ×2.6 | ×0.6 (降) | ×1.6 | 复杂度换效率 |
| 黄 → 白 | ×2.0 | ×1.7 | ×2.9 | 终局放大 |

> 📌 关键规律：**不是在每个梯度均匀增长，而是在特定梯度（蓝→紫、黄→白）出现质变跃迁**。每引入一种新科学包，玩家需要将产能提升 2-5 倍。

| 中间产物 | 被多少下游使用 | 复用类型 |
|----------|---------------|---------|
| 铁板 | **50+ 配方** | 基础材料 |
| 铜板 | **40+ 配方** | 基础材料 |
| 绿电路板 | **~15-20 配方** | 关键中间件 |
| 红电路板 | **~8-12 配方** | 高级中间件 |
| 蓝电路板 | **~5-8 配方** | 顶级中间件 |

### B13. Wube 官方的设计哲学

> 👥 基于 FFF（Factorio Friday Facts）博客历史内容

| 设计原则 | 来源 |
|----------|------|
| "科技应该引导玩家进入新系统，而非只给数值加成" | FFF 多次提及 |
| 新科学包应引入**一种新的物流挑战**（如石油处理、机器人网络），而非单纯增加数值成本 | FFF #150+ |
| 无限科技的目的：在"通关"后给玩家继续优化工厂的理由 | FFF #159 |
| "复杂度增长应该是**跳跃式**的——玩家会在一段时间内舒适，然后新科学包强迫他们彻底重建设施" | FFF 设计理念 |
| 成本曲线刻意设计为"**S 型**"：红绿平缓（学习期）→ 蓝紫急剧（挑战期）→ 黄白再次平缓（精通期） | 👥 玩家社区分析 |

## 主题 C · 通用设计法则 【中高优先】

### C14. GDC / 设计文献总结

> 🤖 + 👥 基于已知 GDC talks 和设计文章

| 来源 | 核心原则 |
|------|---------|
| **Sid Meier's GDC 2010 "Interesting Decisions"** | 每个科技选择都应有取舍（trade-off），而非严格优劣之分 |
| **"Tech Tree Design" (GDC Vault)** | 理想科技树：深度 5-8 层，宽度 3-6 分支，扇出 1.5-3 |
| **Keith Burgun "Clockwork Game Design"** | 科技网络应避免"严格优势路径"和"无选择余地的瓶颈" |
| **"Designing Tech Trees" by David Sirlin** | 伪选择（假的多个路径指向同一结果）比线性更糟糕 |
| **Civilization 设计文档** | 科技树故意不对称——有些线短且强（军事），有些线长且雪球（经济） |

### C15. 科技树常见设计错误

> 👥 社区 + 设计讨论汇总

| 错误 | 说明 | 典型症状 |
|------|------|---------|
| **线性无聊** | 每层只有 1 个可选科技，玩家只是在"点确认" | 玩家不看科技名，只看图标点 |
| **伪选择** | 多个分支但实际指向相同结果，选择无关紧要 | 玩两次选不同路线→结果一样 |
| **解锁了没需求** | 解锁新建筑但玩家还没遇到需要它的场景 | 解锁了高级防御但 AI 还没开始攻击 |
| **盲选负担** | 可选科技太多（>10 个），玩家无从判断 | 新手卡在科技界面几分钟不动 |
| **雪球失控** | 科技领先→经济领先→科技更领先，后期无悬念 | 多人游戏中领先者不可逆 |
| **死胡同科技** | 某个科技既不强也不通往后续，纯占位 | 玩家永远不点它 |
| **时代同步问题** | 科技跑太快但建筑/单位跟不上，解锁了造不起 | 解锁坦克但铁产量还是中世纪水平 |

### C16. 认知负荷：能同时追踪多少个目标？

> 🤖 + 👥

| 研究/经验 | 数字 |
|-----------|------|
| **Miller's Law**（认知心理学） | 工作记忆 7±2 个信息块 |
| **游戏设计经验**（Sid Meier, Civ 系列） | 任何时候可选项控制在 **3-8 个**，超过则分类 |
| **StS 卡牌选择** | 每次 3 选 1，空间最小化 |
| **RimWorld 研究树** | 任何时候可选 ~5-15 个，但用 Tab 分类（建筑/生产/武器/…） |
| **Factorio** | 任何时候可选 ~10-20 个，但玩家习惯"先点一个再排队"，不要求并行列决策 |
| **设计建议** | **软上限 ~8 个同时可选项**，超过时应按域分组或引导玩家聚焦 |

### C17. 金字塔式层宽增长

> 👥 + 🤖

| 形状 | 描述 | 代表游戏 | 优缺点 |
|------|------|---------|--------|
| **金字塔**（上窄下宽） | 每层节点数递增 | Civ 系列 | 前期选择少→学习友好；后期可能雪球 |
| **纺锤形**（中间宽） | 开局少→中期多→终局收敛 | Factorio | 学习期 → 爆发期 → 攻坚期 |
| **倒金字塔**（上宽下窄） | 开局多分支→逐步收敛 | Slay the Spire 牌组 | 前期探索→后期精炼 |
| **平行管道** | 固定宽度一直到底 | RPG 技能树（PoE） | 专精导向，无宽度变化 |
| **菱形网**（网状结构） | 节点间有交叉依赖 | Anno 1800 需求链 | 最复杂但最有机 |

> 📌 **对 Roguelite 的建议**：纺锤形（Factorio 式 S 曲线）最适配——每局的阶段差异感最强。

### C18. Roguelite vs 传统 4X 科技树关键区别

| 维度 | 传统 4X (Civ) | Roguelite |
|------|---------------|-----------|
| 科技树持久性 | 一局 8-40 小时，不变 | 一局 20-60 分钟，每局不同 |
| 成长方式 | 研究解锁新科技 | 随机获得选项，选择后永久生效 |
| 决策空间 | 可规划整局路径（前瞻） | 只能看当前选项+若干步未来 |
| 重置机制 | 基本无重置（除非战败） | 死亡→从头开始（meta 层保留） |
| 宽度策略 | 尽量多分叉 | 每局选 1-2 条专精路线 |
| 伪选择风险 | 低（长局可以补回） | **高**（选错了这局就废了） |
| 设计核心 | 前瞻规划 | **适应性决策**——每次选择都是"用现有信息做最好判断" |

## 主题 D · 其他游戏的形状与层数 【中优先】

### D19. 戴森球计划

> 🤖

| 维度 | vs Factorio |
|------|-------------|
| 生产链深度 | 类似，**8-12 层**（从原矿到戴森球组件） |

### D22. Against the Storm 建筑链

> 🤖（你库里有更详细的分析，这是摘要）

| 维度 | 数据 |
|------|------|
| 建筑链深度 | **2-4 层**（原材料→加工品→奢侈成品） |
| 关键递归 | 木板→板材→工具 / 谷物→面粉→面包 / 树脂→水晶露→奢侈品 |
| 蓝图随机 | 每局从 ~60+ 种建筑中随机获得 ~10-15 个蓝图 |
| 设计特点 | 深度故意短（2-4 层）因为每局受蓝图随机限制——太深会导致"缺关键建筑就卡死" |

### D23. Slay the Spire 牌组构建

> 🤖

| 维度 | 数据 |
|------|------|
| 起手牌组 | **~10-13 张**（基础攻击+防御） |
| 终局牌组 | **~25-35 张**（或精简流 15-20 张） |
| 一局三选一次数 | **~30-40 次**（战斗奖励+商店+事件） |
| 核心引擎成型 | 通常需要 **3-5 张核心引擎卡 + 6-10 张辅助卡** |
| 组合层数 | 典型引擎需要 **2-4 张卡形成联动**（如腐化+黑暗之拥+无实体=3 卡引擎） |
| 关键设计原则 | 引擎卡数=2-4 张（恰好能在爬塔过程中凑齐），超过则太不稳定 |

### D24. "递归层数过多会过载"的临界点

> 👥 + 🤖 社区讨论汇总

| 临界信号 | 标准 |
|----------|------|
| **管理过载** | 同时需要追踪的生产线/需求 >7 种 → 玩家开始"盲做" |
| **依赖地狱** | 一个配方需要 >5 种无法独立的中间产物 → 建厂规划让人放弃 |
| **深度疲劳** | 加工链 >8 层 → 玩家失去"我在造什么"的语义联系 |
| **Factorio 的经验** | 蓝→紫的跃迁是很多玩家的弃坑点（复杂度一次性放大太多） |
| **Anno 的经验** | 工程师→投资人是最容易"断供"的层级（生产链太长导致某环断裂） |
| **设计建议** | 加工链 **≤6 层** 适合大众玩家，**≤10 层** 给硬核玩家留空间；超过 10 层需要极其精细的教程引导 |

## 主题 E · 数值放大与节奏曲线 【中优先】

### E25. 每级成本增长曲线

> 🟢（Factorio 部分）+ 🤖

| 游戏 | 成本增长模式 | 倍率 |
|------|-------------|------|
| Factorio 无限科技（战斗类） | **几何级数**（P[N] = 1000 × 2^(N-1)） | **×2 每级** |
| Factorio 采矿产能 | **算术级数**（+1000 每级） | +1000 固定 |
| Factorio Space Age 产能 | **几何**（×1.5 每级） | **×1.5 每级** |
| Civ6 科技成本 | 随时代和已研究数递增 | 公式复杂，大致每科技 +20-50% |
| StS 卡牌稀有度 | 白/蓝/金的出现率加权 | 非成本增长，是概率分配 |
| 通用经验（城建） | 常用 **×1.3-2.0 每层** | 👥 社区经验 |

### E26. 产能 vs 成本平衡

> 👥 + 🤖

| 原则 | 说明 |
|------|------|
| **产能翻倍时间 ≤ 成本翻倍时间** | 如果成本每级 ×2 但产能只 ×1.5，最终会停滞——Factorio 通过无限科技的新机器/插件/modules 保持产能追赶成本 |
| **质变跃迁 > 均匀增长** | Factorio 的设计：不是在每个科技均匀放大，而是在引入新系统时**一次性跃迁**（如从手工→蓝箱→红箱→机器人） |
| **S 曲线经验** | 每阶段的"舒适区"应持续 **1-3 小时**（玩家在熟练使用当前系统后，才有动力升级到新系统） |
| **反向压力** | Frostpunk 用的是"环境恶化驱动"而非"成本增长驱动"——天越来越冷，不是科技越来越贵 |

### E27. 一个阶段/时代该持续多久？

> 👥 + 🤖

| 游戏类型 | 每阶段时长 | 说明 |
|----------|-----------|------|
| Civ 6（标准速） | 远古/古典每时代 **30-60 分钟** | 后期可能更短（科技加速） |
| Factorio | 红绿期 **2-5 小时** / 蓝紫期 **5-15 小时** / 黄白期 **10-30 小时** | 每级科学包解锁新阶段 |
| Anno 1800 | 每人口层级 **2-8 小时** | 取决于熟悉程度 |
| StS | 每层塔 **2-5 分钟**，一局 **30-60 分钟** | 每层塔 = 一个"微阶段" |
| **Roguelite 建议** | 每阶段 **3-8 分钟**（匹配单局 20-60 分钟） | 阶段过多会感觉"什么都来不及体验" |

## 汇总：形状与递归规则的核心结论

### 1. 科技网络形状

- **推荐：纺锤形**（Factorio 式 S 曲线）：开窄→中宽→收窄
- 每层可选节点：**3-8 个**
- 深度（最长链）：**5-10 层**
- 扇出（一个解锁几个）：**1.5-3**
- 复用度（一个中间产物被多少下游用）：**基础材料 20-50+，高级材料 5-15**

### 2. 递归数值规则

- 成本增长：优选 **几何级数 ×1.5-2.0 每级**（太慢无聊，太快卡死）
- 质变跃迁 > 均匀增长：在关键节点（引入新系统）一次性放大 2-5 倍
- S 曲线节奏：每个舒适期 1-3 小时后引入新压力

### 3. Roguelite 适配

- 单局时长 20-60 分钟 → 每阶段 3-8 分钟
- 选择密度 0.5-2 次/分钟
- 每局专精 1-2 条路线（避免泛而不精）
- 加工链建议 ≤4 层（避免蓝图随机导致的"缺一环卡死"）
