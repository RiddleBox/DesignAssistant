# 03 — 从0设计一条科技/建筑线的通用方法论

> 基于18款游戏建筑-科技-节奏三维解剖的归纳
> 回答三个问题：怎么开始 → 怎么推进 → 怎么收尾

---

## 前置认知：不存在"正确"的建筑树

本次调研最重要的发现：**15款游戏没有两款使用相同的解锁结构**。

| 解锁驱动 | 代表游戏 | 适合场景 |
|----------|----------|----------|
| 科学点/研究包 | Factorio, ONI, RimWorld | 玩家主动分配研究资源 |
| 人口里程碑 | Banished, Cities: Skylines | 成长=解锁，最直观 |
| 随机选择 | Against the Storm, Old World | Roguelite，每局不同 |
| 时代门控 | Civ VI, Humankind | 长线策略，阶段分明 |
| 双树并行 | Frostpunk（科技+法典）, Civ VI（科技+市政）, AoW4（文明+魔典） | 多维度发展有区分 |
| 剧本驱动 | Frostpunk | 强叙事，节奏完全由设计者控制 |
| 资源获取解锁 | Banished（种子/牲畜=贸易） | 地图稀缺性驱动探索 |

**第一原则：先决定你的游戏属于哪一种，再设计解锁结构。不要混合不兼容的模式。**

## Q1：怎么开始？起点怎么定

### 1.1 找到你的「第一个缺口」

从0设计科技线，第一步不是画树，是**找到玩家10分钟内遇到的第一困局**。

| 游戏 | 第一个缺口 | 第一个解锁的建筑 | 设计意图 |
|------|-----------|----------------|----------|
| Factorio | 手工采矿太慢 | 电力采矿机 | 让玩家尝到自动化的甜头 |
| ONI | 氧气不够 | 藻类制氧机 | 解决最基础的生存需求 |
| RimWorld | 没电 | 风力/太阳能 | 从原始→现代的第一步 |
| Frostpunk | 人们需要住所 | 帐篷 | 先解决住的问题，饥饿稍后再来 |
| Banished | 冬天来了 | 伐木场（柴火） | 柴火比食物更先短缺 |
| Against the Storm | 粗制工坊太慢 | 任选一个高级蓝图 | 开局就给你选择权 |
| Timberborn | 旱季缺水 | 水坝 | 让玩家理解"预判性建造" |
| Northgard | 冬天食物耗尽 | 粮仓+猎人 | 为冬天囤积 |

**方法论**：
1. 确定游戏前10分钟的体验
2. 找出那个让玩家自然说出"我要是有个XX就好了"的时刻
3. 第一个解锁建筑就是那个 XX
4. 解锁门槛要极低（1-2步），让玩家在受挫前就拿到

### 1.2 初始状态：几个建筑？

调研数据显示的共识：**3-5个初始建筑 + 1-2个初始决策单元**。

| 游戏 | 初始建筑数 | 内容 |
|------|-----------|------|
| Factorio | 4-5 | 石炉、采矿机、传送带、机械臂（研究解锁前） |
| ONI | 3-4 | 茅厕、人力发电机、研究台、藻类制氧机（早期） |
| Frostpunk | 3 | 工坊（研究）、采集站、帐篷 |
| Banished | 5-6 | 采集小屋、狩猎小屋、伐木小屋、木屋、伐木场、存储区 |
| Thronefall | 4-5 | 金矿、农田、兵营、城墙、塔 |
| Against the Storm | 3 | 伐木工营地、采集者营地、粗制工坊 |

**不可省略的初始建筑**：
- 一个**基础原料获取建筑**（采集/采矿/伐木）
- 一个**初级加工建筑**（炉/工坊/作坊）
- 一个**人口/居住建筑**（住房/营地）
- 一个**存储建筑**（仓库/料堆）

### 1.3 第一条解锁链的设计

第一条链应该是**最短的**（1-2层），且必须让玩家感到"我解决了之前的问题"。

**反例**：第一链就要5步才解锁有用建筑 → 玩家在解锁前已失去耐心
**正例**：Factorio 红瓶自动化 → 第一个研究（自动化1）→ 组装机I（1层深度，5分钟可达）

| 设计决策 | 建议 |
|----------|------|
| 第一链深度 | 1-2层 |
| 第一链解锁时间预算 | 3-8分钟游戏时间 |
| 第一链的心理回报 | 必须是"解决问题"的建筑，不是"锦上添花" |

## Q2：怎么推进？中间段怎么铺开

### 2.1 瓶颈与突破的交替节奏

这是本次调研发现的最核心设计规律：**所有优秀游戏都遵循"瓶颈→突破→新瓶颈→新突破"的波形**。

```
阶段 A（0-10min）：密集解锁，快速成长
阶段 B（10min-2h）：第一个真正瓶颈，玩家必须改变思维
阶段 C（2h-10h）：多个分支并行，玩家有选择权
阶段 D（10h-30h）：瓶颈密集期，需要系统优化
阶段 E（30h+）：终局冲刺或无限优化
```

**共性规则**：

| 规则 | 说明 | 案例 |
|------|------|------|
| **新手蜜月期** | 前30分钟密集解锁5-10个新东西 | Factorio(红+绿瓶科技群), ONI(基础研究) |
| **成人礼瓶颈** | 一次"换脑子"的大瓶颈 | Factorio石油化工, ONI电解器, RimWorld微电子 |
| **分叉期** | 瓶颈突破后给出多条并行路线 | Frostpunk多线Tier 2, Civ VI时代后分支 |
| **渐密期** | 后期解锁越来越难，间隔越来越长 | 所有游戏的通用模式 |

### 2.2 线性 vs. 分支：怎么选

| 结构 | 适合 | 案例 | 优点 | 缺点 |
|------|------|------|------|------|
| **纯线性** | 回合制/短局/教学向 | Thronefall, Banished | 节奏可控，不会让玩家迷失 | 重玩性低 |
| **宽分支+浅深度** | 需要同时管理多系统的游戏 | Frostpunk(5线×4层), Northgard | 给予选择感，不强制全部点完 | 可能分散注意力 |
| **深树+交叉依赖** | 工程/自动化 | Factorio(7层最高), ONI | 深度满足感，链越长越有成就感 | 可能卡瓶颈 |
| **随机池** | Roguelite | Against the Storm, Old World | 每局不同，重玩性极高 | 运气成分大 |

**选择逻辑**：
- 你的游戏玩家一局玩多久？<2h → 宽分支或随机池；>10h → 深树+交叉依赖
- 你的游戏有多条路线吗？有文明/种族区分 → 分支允许差异化；单一文明 → 线性或宽分支
- 你的游戏重玩性来源是什么？如果靠建筑组合 → 随机池；靠不同路线 → 分支；靠优化提升 → 深树

### 2.3 什么时候给玩家新东西，什么时候让玩家消化

| 阶段 | 时限 | 设计目标 | 策略 |
|------|------|----------|------|
| **前15分钟** | 每1-2分钟一个解锁 | 建立"成长=解锁"的心理链接 | 小块快速喂食 |
| **15分钟-1小时** | 每3-5分钟一个解锁 | 让玩家习惯一个系统后再给下一个 | 每次解锁后给2-3分钟"试用期" |
| **1-5小时** | 每10-15分钟一个解锁 | 系统开始交叉，给玩家选择权 | 同时开放2-3条分支，让玩家选 |
| **5-20小时** | 每30-60分钟一个解锁 | 每次解锁都是质变 | 减量增质：少给但每个都要实质改变玩法 |
| **20小时+** | 1-3小时或更长 | 终局冲刺/无限优化 | 不是"更多新建筑"，是"更好用旧建筑" |

**判断玩家是否需要消化**：看他们是否已经用新解锁的建筑完成了至少一次从输入到输出的完整循环。如果没有，先别给下一个。

### 2.4 跨游戏共性：四种"审判时刻"

几乎所有优秀样本都在节奏中嵌入了**周期性审判**：

| 审判类型 | 代表游戏 | 间隔 | 作用 |
|----------|----------|------|------|
| **灾难周期** | Frostpunk暴风雪, Timberborn旱季, ONI热量积累 | 5-15h（缓慢积累→爆发） | 检验所有前期投入是否足够 |
| **日夜/季节周期** | Thronefall日夜切换, Northgard冬夏交替 | 2-5min（短周期） | 强制切换行为模式 |
| **人口波动** | Banished人口波, RimWorld袭击波 | 30min-2h | 创造"刚升上去又掉下来"的紧张 |
| **时代审判** | Civ VI时代评分, Humankind时代切换 | 1-3h | 评价过去阶段，决定下一阶段方向 |

**设计启示**：你的游戏至少要嵌入一种审判时刻。如果没有，玩家的建筑选择就没有紧迫感。

## Q3：怎么收尾？终局怎么定位

### 3.1 终局的六种角色模型

| 终局角色 | 代表 | 机制 | 适合 |
|----------|------|------|------|
| **终结者** | Factorio火箭, Frostpunk终局暴风雪 | 明确终点，到达即通关 | 有明确胜利条件的游戏 |
| **无限放大器** | Factorio无限科技, ONI太空材料 | 可无限升级但回报递减 | 沙盒/自动化游戏 |
| **新游戏+入口** | Against the Storm城堡升级 | 通关解锁跨局永久升级 | Roguelite |
| **美学展示** | Cities Skylines地标建筑, RimWorld飞船 | 建了没用但好看/有成就感 | 创意/建造游戏 |
| **路线终局** | Civ VI胜利路线, AoW4魔典终章 | 不同路线有不同的终局状态 | 多路线策略游戏 |
| **无终点** | Banished（无尽生存） | 只要不崩就不结束 | 生存模拟 |

### 3.2 科技线是否有终点？

| 有终点 | 无终点 |
|--------|--------|
| Factorio（火箭=主线终点，太空时代=DLC扩展） | Factorio（无限采矿产能科技） |
| Frostpunk（剧本结束=终点） | ONI（时空裂痕=理论终点但多数玩家在此之后继续） |
| Against the Storm（每局胜利=终点） | RimWorld（飞船发射=可选终点，多数玩家不发射） |
| Thronefall（每局胜利=终点） | Banished（没有终点概念） |
| Northgard（征服胜利） | Cities Skylines（无尽建造） |

**设计建议**：
- 新手可见终点（10-30h可达）→ 给明确目标感
- 老手无限延伸（超过终点后的内容）→ 给持续动力
- 两个都要有，但不是同时给

### 3.3 终局设计的常见错误

| 错误 | 症状 | 修复 |
|------|------|------|
| **终局太远** | 玩家在中期就流失了 | 插入"里程碑式终点"（如 Factorio 每色瓶=一个小终点） |
| **终局太近** | 通关后无事可做 | 加入无限升级/新游戏+/高分模式 |
| **终局与前期脱节** | 终局需要的建筑和前期完全无关 | 终局建筑应该放大前期建筑的价值，不是废弃它们 |
| **终局只有一种路线** | 不管你前期怎么走，最后都一样 | 给不同路线不同的终局状态 |

## 综合方法：从0设计一条科技线的10步工作流

```
Step 1: 定义10分钟体验
  → 玩家看到的第一个缺口是什么？
  → 写下3-5个基础建筑

Step 2: 设计第一条解锁链
  → 1-2层深度，3-8分钟可达
  → 解锁的是"解决问题"不是"锦上添花"

Step 3: 确定解锁驱动模式
  → 研究点数？人口门槛？随机选择？时代门控？双树？
  → 决定后不再改变（可以加副树但不换主模式）

Step 4: 画出建筑类型谱系
  → 按"原料→加工→存储→消费→研究→服务→防御"分类
  → 标注类间依赖关系

Step 5: 设计瓶颈位置
  → 成人礼瓶颈应该在哪里？（通常在1-3小时处）
  → 这个瓶颈需要玩家"换脑子"吗？

Step 6: 设计审判时刻
  → 选择一种周期审判：灾难/季节/人口波/时代评分
  → 审判间隔决定游戏节奏的快慢

Step 7: 铺开分支
  → 瓶颈之后给2-3条并行分支
  → 每条分支有明确的"身份标签"（工业/文化/军事/信仰…）

Step 8: 设定解锁间隔
  → 前15分钟：1-2分钟/解锁
  → 15分-1小时：3-5分钟/解锁
  → 1-5小时：10-15分钟/解锁
  → 5小时+：30分钟+/解锁，每次质变

Step 9: 设计终局
  → 选择终局角色（终结者/放大器/新游戏+/展示/路线终局/无终点）
  → 30小时内可见的"新手终点" + 远超30小时的"老手延伸"

Step 10: 反向验证
  → 从终点倒推：玩家走到终点时，应该经历了所有建筑类型吗？
  → 检查：有哪个建筑在整个链条中"孤立"（既不被依赖也不依赖别人）？
  → 检查：瓶颈间距是否均匀？（全部挤在一起 = 灾难）
```

## 对文明Roguelite的直接启示

基于调研结论，对文明演化Roguelite的建筑/科技线设计的初步建议：

### 可迁移的设计模式

| 来源 | 可迁移模式 | 迁移方式 |
|------|-----------|----------|
| Against the Storm | 随机蓝图选择 | 每局文明从预定义建筑池中随机抽取部分可用建筑 |
| Frostpunk | 双树结构 | 科技树（物理建设）+ 制度树（社会治理/信仰）= 双线并行 |
| Civ VI | 时代门控+尤里卡 | 不同文明阶段（部落→城邦→帝国→？）有明确的阶段建筑池 |
| RimWorld | AI Storyteller节奏 | 危机/机遇/事件的节奏由系统控制，而非玩家决定何时遇到 |
| Banished | 人口驱动解锁 | 人口增长自然触发新建筑/制度可选 |
| Factorio | 瓶颈自生成目标 | 当前最慢的环节自动成为玩家的"下一步目标" |

### 应避免的设计

| 来源 | 应避免 | 原因 |
|------|--------|------|
| Factorio | 完整线性科技树 | 不适合 Roguelite（每局相同=没有重玩性） |
| Frostpunk | 剧本强控节奏 | 限制了文明路线的自由演化 |
| Civ VI | 提前可见的完整科技树 | 削减了探索感和路线不确定性 |
| Banished | 纯人口驱动+无选择 | 剥夺了玩家主动决策的空间 |

### 建议的初始架构（待验证）

```
主驱动：随机池选择（类似 Against the Storm）
副驱动：事件触发解锁（类似 Frostpunk 法典树的"冷却+选择"）
节奏器：阶段审判（类似 Timberborn 旱季 or 四季）
建筑分类：少而精（采集→加工→治理→信仰，4类×每类3-5个建筑）
终局：路线识别（不设定单一终点，由建筑组合+历史事件自然形成文明身份）
```
