## 核心建议：分级混合策略（推荐）

借鉴文档 Q5 的思路，但做关键修正——**不按批次大小简单分级，而是按信号密度和复杂度分级**：

| 场景 | 策略 | 核心机制 |
|------|------|----------|
| **稀疏批次**（信号数 ≤ 20 或跨域信号 < 5） | 全量直送 Step C | 取消 Step A，避免过度处理 |
| **中等密度**（20-50 条，跨域信号 5-15） | **方案 E + A 混合** | Step A 做角色标注但不硬分组，作为软建议送入 Step C |
| **高密度复杂批次**（50+ 条，跨域信号 > 15） | **方案 D（机会假说生成）** | 轻量 LLM 生成假说 → 信号聚类 → 每假说独立验证 |

**关键修正点**：文档 Q5 的阈值基于"信号数量"，但核心矛盾是**跨域逻辑链的密度**。20 条全来自不同领域的信号，比 50 条同领域信号更需要精细处理。

## 针对 Q1-Q5 的具体建议

### Q1：如何在不断开跨域逻辑链的前提下控制 context 长度？

**推荐方案：动态信号池 + 相关信号预加载**

```
Step C 输入结构：
├─ 核心信号（5-8 条）：当前判断的机会相关信号
├─ 候选伙伴信号（10-15 条）：基于角色互补从全量中检索
└─ 领域概览（3-5 条）：各关键领域的代表性信号摘要
```

实现机制：
1. **Step A 不输出硬分组，输出"信号关系图"**（轻量级，haiku 级 LLM 或规则）
2. Step C 按需加载：先判断核心信号，再动态请求相关信号补充
3. 用 Signal Store 的跨批次匹配能力，将历史相关信号作为"候选伙伴"预加载

这比"切分窗口"（方案 C）更优，因为窗口切分是**空间维度**的硬分割，而动态加载是**逻辑维度**的软关联。

### Q2：方案 D（机会假说生成）的可行性？

**可行，但需要关键补丁解决"遗漏"问题**：

| 风险 | 补丁方案 |
|------|----------|
| LLM 假说遗漏 | **双轨生成**：① LLM 生成假说 ② 规则引擎基于历史高频模式生成候选假说，取并集 |
| 信号质量参差 | 假说生成阶段**不看信号质量分数**，只看信号类型组合是否构成"机会模式" |
| 与 Signal Store 整合 | 假说生成时**主动查询 Store**："历史上哪些信号组合曾构成机会？"作为模式参考 |

**具体实现**：
```python
# 伪代码
def generate_hypotheses(signals, store):
    # 轨道 1：LLM 基于当前信号生成
    llm_hypotheses = llm_generate(signals_summary)
```

### Q3：不依赖 LLM 的粗筛方案？

**推荐：图神经网络（GNN）或结构化规则 + 向量检索的混合方案**

核心洞察：文档提到"逻辑互补" vs "语义相似"——这实际上是**结构化关系** vs **非结构化相似**的区别。

**实现思路**：

1. **信号结构化表示**（在 2.1 解码阶段增强）：
   ```python
   {
       "signal_id": "s001",
       "what_changed": "监管政策",      # 变化主体
       "change_direction": "收紧",      # 变化方向  
       "affects": "中小发行商",         # 影响对象
       "impact_scale": "区域性",        # 影响范围
       # ... 保留原有字段
   }
   ```

2. **基于规则的互补匹配**：
   ```python
   COMPLEMENT_RULES = [
       # 监管收紧 + 资金充足 + 标的便宜 = 整合机会
       ({"what_changed": "监管政策", "change_direction": "收紧"},
        {"what_changed": "资本动向", "change_direction": "增加"},
        {"what_changed": "市场估值", "change_direction": "下降"}),
       # ... 其他模式
   ]
   ```

3. **向量检索兜底**：对规则未覆盖的信号，用 embedding 找语义相似的历史信号

**优势**：规则层保证跨域组合的召回，向量层保证覆盖度，均不依赖 LLM 做复杂推理。

**增强方向**：

### Q5：分级策略的细化建议？

**修正版分级策略**：

| 维度 | 阈值 | 策略 | 关键参数 |
|------|------|------|----------|
| **信号数量** | ≤ 15 | 全量直送 | 无 Step A |
| | 16-40 | **软建议模式** | Step A 输出角色标注 + 候选关系图，Step C 全量接收但优先关注建议关系 |
| | > 40 | **假说驱动模式** | Step A 生成 5-8 个机会假说，每个假说聚类 8-12 条信号独立送 Step C |
| **跨域密度**（不同领域信号数）| ≤ 3 | 领域分组可接受 | 简单按领域分组 |
| | > 3 | 必须角色/假说驱动 | 禁用纯领域分组 |

**关键决策逻辑**：
```python
def select_strategy(batch):
    domain_diversity = len(set(s.domain for s in batch.signals))
    
    if len(batch) <= 15:
        return "FULL_DIRECT"
    elif len(batch) > 40 or domain_diversity > 3:
        return "HYPOTHESIS_DRIVEN"  # 方案 D
    else:
        return "SOFT_SUGGESTION"     # 方案 E + A
```
